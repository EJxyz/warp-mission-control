# About WARP Mission Control

**WARP Mission Control** is a browser-based situational-awareness dashboard that visualizes weather anomalies and hypothetical electromagnetic-pulse (EMP) events across North America on a single interactive map. It presents like an operational mission-control console — a dark, map-centric, graph-heavy interface with live storm markers, forecast cones, animated overlays, timeline playback, and analytics panels — but it is a concept and research build rather than an authoritative forecasting product. Its purpose is to bring two very different kinds of information into one coherent view: real, observed weather hazards on one side, and modeled "what-if" pulse scenarios on the other, so a user can begin to reason about risk and resilience for critical infrastructure under both natural and hypothetical threats.

I built it because assessing infrastructure risk usually means juggling separate tools, formats, and mental models for real hazards versus simulated scenarios — and that fragmentation makes it easy to conflate what is actually happening with what is merely modeled. WARP's central design principle is a strict, enforced separation between real and simulated data. Every object on the map carries a provenance tag — observed, forecast, or simulated — that is validated in the data model and surfaced everywhere in the interface: simulated objects are visibly marked, real observations cannot be edited or dragged, and an on-screen status notice always states which data source is active. The EMP layer is deliberately fictional and clearly flagged as such, serving as a scenario tool rather than a claim about real events. This discipline is the foundation for the longer-term goal: a platform for infrastructure hazard and resilience assessment, where real weather feeds and modeled pulse effects can be examined side by side without ever being mistaken for one another.

It is built as a dependency-free web application using vanilla HTML, CSS, and JavaScript ES modules — no framework and no build step — which keeps it lightweight, transparent, and easy to host as a static site. [Leaflet](https://leafletjs.com/) powers the mapping and [Chart.js](https://www.chartjs.org/) drives the analytics. The heart of the system is a source-abstraction data layer: the interface never reads raw API responses directly, but instead consumes normalized entities produced by pluggable source adapters. A live adapter ingests real [NWS/NOAA](https://www.weather.gov/documentation/services-web-api) weather alerts (US coverage), a mock adapter provides built-in concept data for offline use, and an adapter for NHC tropical cyclones is included but parked behind a proxy requirement due to browser cross-origin restrictions — a limitation the app documents honestly rather than hiding. The codebase is organized into focused, tested modules — data model, sources, map, panels, charts, timeline, workspaces, and navigation — with a Node-based automated test suite and continuous integration guarding the data-layer logic against regressions. It evolved deliberately from a single monolithic file into this modular, verifiable structure, prioritizing correctness, honest data provenance, and a clear architectural path toward becoming a genuine infrastructure-resilience tool rather than a purely cosmetic demo.
